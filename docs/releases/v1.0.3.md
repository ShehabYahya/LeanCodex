# v1.0.3 — LeanCodex

v1.0.3 is the first release under the **LeanCodex** name.

LeanCodex keeps Codex focused on architecture, decisions, and review while an already-running DeepSeek Harness session handles bounded long-running execution. The durable session bridge remains the same: exact assignment correlation, compact finalized output, resumable cursors, lifecycle state, and bounded evidence reads.

## What changed

- Public branding is now **LeanCodex** across the README, plugin marketplace display name, MCP display name, skill display surface, security/contributing docs, and repository metadata embedded in review bundles.
- Installation now points to `ShehabYahya/LeanCodex`.
- The plugin manifest is versioned **1.0.3** and points at the renamed repository.
- Release publishing is now tag-driven and verifies that the Git tag matches the plugin manifest version before tests and publication run.
- The deterministic supervision suite and MCP stdio contract test are release gates.

## Compatibility

The rename intentionally does **not** change these stable internal surfaces:

- plugin ID: `dsh-cli-session`;
- plugin directory: `plugins/dsh-cli-session/`;
- session skill ID: `dsh-cli-session`;
- orchestrator skill ID: `dsh-orchestrator`;
- MCP server key: `dshCliSession`;
- MCP tool names such as `dsh_send_prompt` and `dsh_wait_output`;
- local assignment state path under `.dsh-cli-session/`.

Existing installations and local correlation state therefore do not need a migration solely because of the LeanCodex rebrand.

## Installation

```bash
codex plugin marketplace add ShehabYahya/LeanCodex
```

Restart ChatGPT Desktop, open the plugin directory, select the marketplace, and install **LeanCodex**.

## Verification

Before publishing the tag, CI must pass:

```bash
python3 -m unittest -v tests/test_supervision.py
python3 tests/test_mcp_stdio.py
```

The release workflow repeats those checks on the release tag before creating the GitHub release.

## Known limits

- Delivery remains wait-based through ordinary MCP tool results; unsolicited model wakeup/push is not claimed.
- Runtime compatibility depends on the locally installed DeepSeek Harness version.
- The project currently retains its existing proprietary license metadata.
