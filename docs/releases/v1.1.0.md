# v1.1.0 — Portable install hardening

LeanCodex v1.1.0 hardens fresh installs and cross-platform startup without changing the DSH supervision contract, tool names, schemas, assignment correlation, cursor behavior, or wait semantics.

## Fixed

- replaced the machine-specific `python3` MCP launch command with a small Node launcher that finds Python 3.11+ across Linux, macOS, and Windows;
- added a pinned runtime dependency file and automatic private-cache bootstrap for `mcp==2.2.0` when the selected Python environment does not already provide it;
- kept the selected Python environment untouched: bootstrap dependencies are installed under LeanCodex's own cache;
- made the MCP server honor `DSH_HOME`;
- added `LEANCODEX_CREDENTIALS_FILE` for DSH installations that use a non-default credential-store path;
- added `LEANCODEX_DSH_URL` for DSH Web instances using a non-default loopback port;
- added `LEANCODEX_PYTHON` and `LEANCODEX_RUNTIME_DIR` overrides for explicit runtime control;
- added real inter-process assignment-store locking on Windows using `msvcrt`, while retaining `fcntl` on POSIX;
- stopped rejecting valid absolute project/session paths merely because the MCP process cannot see the same filesystem namespace as DSH;
- made CWD session matching normalize path spelling without resolving through the local filesystem.

## Verification

CI now runs the deterministic supervision and MCP contract suites on Ubuntu, Windows, and macOS. It also creates a fresh Python virtual environment with no MCP SDK, starts LeanCodex through the exact `.mcp.json` launcher, verifies that the private runtime bootstrap occurs, and confirms the advertised MCP tools.

The release workflow repeats the clean-install smoke test before publication.

## Compatibility

The following remain unchanged:

- plugin ID `dsh-cli-session`;
- MCP server key `dshCliSession`;
- all MCP tool names and tool schemas;
- assignment/request correlation behavior;
- signed cursor format and local assignment-store path;
- wait/output semantics;
- default DSH Web URL `http://127.0.0.1:3080`;
- default DSH home `~/.dsh`.

Existing installations require no state migration.
